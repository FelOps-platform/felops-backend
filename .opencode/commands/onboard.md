Onboard without assuming a stack or reading the entire repository into one context.

1. Read AGENTS.md and docs/project-context.md. Check agent-metadata.md for current verified facts.
2. Use the explorer subagent for broad mapping when available; otherwise inspect relevant manifests, entry points, and docs directly. Follow `docs/agent-routing.md`: bind the explorer to the fast, low-cost tier at launch when supported, and state when inherited-only roles cannot enforce it.

4. Keep product context in docs/project-context.md. Do not turn exploratory ideas into requirements.
5. Report the verified overview and material unknowns. Ask only questions that block the next requested task.

Do not implement product changes during onboarding. If the user requested setup or implementation as part of this request, continue within that explicitly stated scope.
