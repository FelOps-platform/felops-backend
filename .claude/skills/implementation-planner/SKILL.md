# Implementation Planner

For substantial work, write docs/work/<issue-id-or-short-slug>/plan.md from docs/templates/implementation-plan-template.md, alongside the feature brief.

Include:

- Goal and non-goals.
- Scope and constraints from docs/project-context.md.
- Stack and conventions supported by repository evidence; use the explorer subagent for broad mapping when available.
- Affected files and modules.
- Step-by-step implementation.
- Focused verification commands and expected evidence.
- Risks, mitigations, and rollback.

A plan organizes work the user has already authorized. Ask only about material unresolved decisions or actions that need explicit authorization. If the user requested planning only, present the plan and stop.
